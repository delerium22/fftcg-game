## HIGH

**`decodeAction` can return an observably different command from the one the tree evaluated.** List-valued commands are sorted into keys (`packages/ai/src/ismcts/keys.ts:214`, `:224`, `:226`, `:228`), simulations apply the original candidate (`packages/ai/src/ismcts/search.ts:372`, `:377`), but the final result prefers a freshly decoded command (`packages/ai/src/ismcts/search.ts:417`). Decoding consumes refs in sorted-key order (`packages/ai/src/ismcts/keys.ts:357`, `:376`), while the engine preserves command order in the Break Zone and resolution frame (`packages/engine/src/cp.ts:105`, `packages/engine/src/phases.ts:79`, `packages/engine/src/resolve.ts:485`). `observationKey` then treats Break-Zone order as significant (`packages/ai/src/ismcts/keys.ts:407`). A direct probe showed `[V-F7,V-F1]` being evaluated, decoded as `[V-F1,V-F7]`, and producing different Break-Zone observations. The round-trip test checks only re-keying and legality, not transition equivalence (`packages/ai/test/ismcts-keys.test.ts:264`). **Fix:** Return `rootCommands.get(best.key)` as the authoritative live command, or canonicalize/decode commands before every tree `apply`. Add tests comparing post-apply `ObservationKey`s for original versus decoded casts, discards, targets, and assignments.

**The rollout command cap is not a hard bound.** `rolloutToCap` gives Greedy an infinite internal budget and, after reaching the cap, invokes an exempt `resolveForcedDecisions` tail (`packages/ai/src/ismcts/search.ts:266`, `:278`). That helper selects and applies actual player commands (`packages/ai/src/greedy.ts:71`, `:77`, `:79`). The test explicitly demonstrates `cap: 0` performing additional applies while still reporting zero commands (`packages/ai/test/ismcts-search.test.ts:367`, `:371`, `:375`). This violates D-6 and creates exactly the unbounded work tail that will hurt Worker latency/cancellation. **Fix:** Count every trajectory command, including forced prompts, against the cap; use a bounded pending-aware leaf evaluation or a separately bounded settlement allowance. Add a hard apply/work cap as the Worker-facing safety bound.

## MEDIUM

**Search still depends on semantically meaningless hand ordering through incomplete comparators.** `observationKey` declares the hand a multiset (`packages/ai/src/ismcts/keys.ts:461`), but determinisation preserves the root hand order (`packages/engine/src/determinise.ts:44`). Hand-size discard sorts only by `cardValue` (`packages/ai/src/candidates.ts:284`), while payment selection has cost-only tie comparators (`packages/ai/src/payment.ts:21`, `:75`, `:103`). Reordering an otherwise identical hand can therefore change the sole offered discard or preferred payment; sorting action keys cannot recover an action already pruned away. **Fix:** Use total semantic comparators—value/cost, source kind, card code, element, then canonical public ref—and test searches from hand-order permutations for identical commands and diagnostics.

**The promised D2 worker protocol is not actually represented by the seam.** `SearchInput` carries decks on every call (`packages/ai/src/ismcts/keys.ts:491`), while its `PlayerView` also contains the complete definitions (`packages/engine/src/view.ts:11`); the wrapper explicitly proposes posting this whole object unchanged (`packages/ai/src/ismcts/agent.ts:30`). There are no init/request/result types carrying `requestId`, generation, or decision index. The search itself is synchronous and cloneable, but D2 must invent an adapter and repeatedly clone static data if it follows the current contract literally. **Fix:** Define structured-cloneable `WorkerInit`, `WorkerSearchRequest`, and `WorkerSearchResult` types now; store decks/definitions once in the worker and rehydrate the core input there.

**An invalid CLI seed silently collapses all tournament pairs onto seed zero.** `--seed` alone bypasses the strict parsers (`apps/cli/src/main.ts:25`). For `NaN`, `opts.seed + i` remains `NaN` (`apps/cli/src/mirror.ts:182`), and `seedRng` coerces it to zero (`packages/engine/src/rng.ts:3`). A typo can therefore produce repeated identical pairs and a meaningless narrow bootstrap interval. **Fix:** Strictly parse and validate the seed as a finite integer and validate it again at `mirrorTournament`’s programmatic boundary.

## LOW

The choose-first decision means those are not equivalent. **Fix:** Correct the description/rename it to `playerSeatBias`; record actual `firstPlayer` if first-turn bias is wanted.

## HIGH

**`settle()` can break a chosen target before resuming the effect that targeted it.** Ramuh may select damage then Haste and legally target the same 5000-power Forward for both (`packages/cards/src/abilities.ts:176`, `packages/cards/src/abilities.ts:180`). The second prompt is exposed while lethal damage remains (`packages/engine/src/resolve.ts:177`), but after its answer `settle()` runs rule processes before resuming (`packages/engine/src/apply.ts:36`), removes the target, and `grantKeyword` silently skips it (`packages/engine/src/resolve.ts:239`). A direct probe reproduced the stale candidate and missing Haste event. **Fix:** When an answer clears an ability pending, resume the active frame before running rule processes; keep the frame logically atomic across UI commands, then run the trailing rule-process pass after it finishes.

## MEDIUM

**The transition snapshot implementation watches the card that moved, not cards observing the move.** `enqueueZoneTriggers` looks up abilities on `t.card` (`packages/engine/src/rules.ts:61`), whereas Lightning’s trigger belongs to a potentially different Forward watching an opponent’s card enter the Break Zone (`packages/cards/data/cards.json:272`). This also loses Lightning if both cards leave simultaneously—the exact prior-review hazard. Direct `breakCard` bypasses transitions entirely (`packages/engine/src/resolve.ts:220`), while every current transition records a null cause (`packages/engine/src/rules.ts:49`). **Fix:** Snapshot all pre-transition trigger sources, match their abilities against the complete transition batch, and route direct breaks/returns and damage-caused moves through one source-aware transition pipeline.

**The budget-starved Ramuh mode policy can choose a provably redundant pair.** Modes are valued independently and summed (`packages/ai/src/candidates.ts:205`), then the highest individual modes become the first answer (`packages/ai/src/candidates.ts:237`). Against an active 5000-power Prishe with a fresh friendly Forward, it ranks damage+dull first even though both target Prishe; damage+Haste kills the same card and unlocks an attacker. An exhausted budget scores only that first answer (`packages/ai/src/greedy.ts:87`). The separate chip-vs-kill defect is fixed at `packages/ai/src/candidates.ts:111`. **Fix:** Enumerate the at-most-seven Ramuh mode subsets and rank each jointly, applying its nested target policy in printed order so interactions and redundancy are visible.

**A continuation by itself is treated as settled and becomes permanently orphaned.** `settle()` exits and resets based only on `active` and `queue` (`packages/engine/src/apply.ts:39`, `packages/engine/src/apply.ts:45`), although `drainResolution` is the only code that consumes the continuation (`packages/engine/src/resolve.ts:324`). AI diagnostics likewise count only frames (`packages/ai/src/greedy.ts:130`). A probe left `enterAttackDeclaration` in `main1` indefinitely with invariants still green. **Fix:** Introduce a shared `hasResolutionWork()` including `continuation`; use it in settlement, invariants, and AI diagnostics. Generalize the continuation payload before EX Burst needs a combat-resolution continuation.
